# GGUF Compress V3 — adaptive rank + sparse residual + packed Q4 runtime

V3 is an additive experimental format. It does not replace the V1/V2 files, so all three generations can be benchmarked side by side.

## 1. Adaptive rank

Instead of forcing rank 8/16/32 on every matrix, V3 computes one randomized-SVD basis up to the maximum allowed rank and tests truncated candidates in ascending order. The first rank satisfying the requested relative RMSE is selected.

Default candidates:

```text
4, 8, 16, 32, 64, 128, 256
```

Role caps keep obviously smaller projections from spending unnecessary rank:

```text
attn_k                    <= 32
attn_q / attn_v / attn_o <= 64
ffn_up/gate/down          <= 128
output                     <= 64
```

Run:

```bash
gguf-compress compress-v3 model.gguf model.v3.gguf \
  --ranks 4,8,16,32,64,128 \
  --target-rel-rmse 0.20 \
  --qbits 4 \
  --residual-density 0.01
```

Every tensor manifest entry records the complete rank search, chosen rank, pre-residual RMSE/cosine and post-residual RMSE/cosine.

## 2. Sparse residual correction

V3 approximates a matrix as:

```text
W ~= A @ B + R_sparse
```

The residual is stored row-wise. For every output row, only the largest `density * in_features` errors are retained. The correction stores:

- int32 column indices in the portable GGUF container;
- int8 correction values;
- one FP16 scale per output row.

At runtime the correction is applied directly as `X @ R_sparse.T`; a dense residual matrix is not needed.

## 3. Native packed-Q4 export

After `compress-v3`:

```bash
gguf-compress export-native-q4 model.v3.gguf model.native-q4.gguf
```

For supported central linear weights, the native file stores:

```text
<original-name>                         tiny proxy only
<original-name>.__gguf_lr_q4_a_data    packed Q4 A
<original-name>.__gguf_lr_q4_a_scale   FP16 row scales
<original-name>.__gguf_lr_q4_b_data    packed Q4 B
<original-name>.__gguf_lr_q4_b_scale   FP16 row scales
<original-name>.__gguf_lr_res_cols     optional residual columns
<original-name>.__gguf_lr_res_values   optional residual int8 values
<original-name>.__gguf_lr_res_scales   optional residual FP16 scales
```

Unsupported factorized tensors are reconstructed during export so the runtime does not silently receive a malformed tensor.

## 4. Direct Q4 C++ kernel

`cpp/lowrank_q4_kernel.h` implements the CPU reference operator:

```text
X -> packed Q4 B -> rank-sized hidden -> packed Q4 A -> Y
                                      + sparse residual
```

It decodes Q4 nibbles inside the dot product and never materializes dense A, dense B, or dense W. The only dynamic intermediate is `rank` floats per input row.

Build the standalone benchmark:

```bash
g++ -std=c++17 -O3 -Icpp cpp/bench_lowrank_q4.cpp -o bench_lowrank_q4
./bench_lowrank_q4 1024 16 4 5
```

The scalar reference benchmark is for arithmetic/path validation, not a claim against optimized BLAS/GGML kernels. On the development CPU environment, `1024 x 1024`, rank 16, batch 4 produced about 26.5x speedup over the same scalar dense reference with max absolute numerical difference around 0.0053.

## 5. llama.cpp CPU integration patch

The V3 patcher targets exactly:

```text
llama.cpp commit 5f436dddb440a288ee5611d7d1eca564a6aca9f4
```

Apply:

```bash
python llama_cpp_v3/apply_patch.py /path/to/llama.cpp
cmake -S /path/to/llama.cpp -B /path/to/llama.cpp/build -DGGML_CUDA=OFF
cmake --build /path/to/llama.cpp/build --target llama -j
```

The patched loader recognizes the tiny original-name proxy and packed factor companions, keeps V3 factor storage on CPU, and replaces the ordinary dense `build_lora_mm()` path with a single `ggml_custom_4d` CPU node calling the packed-Q4 kernel.

This V3 custom node is intentionally CPU-first. V2 remains the portable fallback because it expands low-rank execution into two ordinary `ggml_mul_mat` nodes and can therefore use existing CPU/CUDA/Metal/Vulkan/SYCL backends. A production GPU V3 should replace the CPU custom node with backend-specific CUDA/Metal/Vulkan kernels.

## 6. Real llama-bench comparison

Once dense and patched-native GGUFs are available:

```bash
gguf-compress real-benchmark \
  /path/to/llama-bench \
  model-original.gguf \
  model.native-q4.gguf \
  --prompt-tokens 512 \
  --gen-tokens 128 \
  --repetitions 5 \
  --n-gpu-layers 0
```

The report includes:

- file size and compression ratio;
- prompt-processing tokens/s;
- generation tokens/s;
- speedup ratios;
- peak RSS sampled from `/proc`;
- best-effort NVIDIA process-memory delta from `nvidia-smi` when available;
- raw `llama-bench` JSON rows for auditability.

`llama-bench` itself does not include tokenization/sampling time; the report preserves that limitation rather than presenting it as full request latency.
